    All three passed. A failure would name the check and show what the code actually returned.

    One file, inside the allowed scope. The patch waits for you; your project is untouched until you apply it.

Every result and outcome Quarterback can report
Pass
Every agreed check and the project’s tests passed.
Fail
A check or test failed, or a file outside the allowed scope changed.
Partial
Some checks couldn’t be decided.
Unresolved
The evidence couldn’t settle it, for example a requirement with no runnable check.
Blocked
The run stopped before anything was checked, for example because the requirements weren’t approved. It says nothing about whether a change would pass.
Error or cancelled
The run itself broke, such as a timeout, or was stopped.

Progress · updated November 8, 2026

Where Quarterback stands.

What works today, what we’re fixing, and what we haven’t proven yet.

Available now

Run, check and review a change

  • Claude Code works in an isolated workspace against requirements you approve; your tests and the agreed checks run on its change, and you get a patch to review. The run above
  • Quarterback stops with a clear message when a drafted requirements list is invalid, or would only allow changes to off-limits files. Merged November 4 and 5. Evidence
  • Signing up emails you the setup guide right away. Live since November 8.

Being improved

Writing the requirements automatically

  • Most automatic drafts are still rejected, so trials start from a list a person writes or reviews. Measurements
  • The full setup walkthrough last passed on October 12, on an earlier version. We’re confirming it on the current one. Record

Being evaluated

Does it save you review time?

  • Not established. Two early, small comparisons with Claude Code alone showed no measured advantage. Evaluation notes
  • Next: compare the two on tasks whose results are checked independently.
