What Quarterback does

A checklist before the work, evidence after it.

AI coding assistants are fast, but their changes can look finished while missing part of what was asked. Today someone has to read every line to be sure. Quarterback adds structure around the assistant so you can see what was checked and how it turned out.

  1. 01

    Agree on the requirements

    A short list: what must be true, which files may change, and checks that can be run automatically. You approve it. The coding assistant doesn’t start before you do.

  2. 02

    The AI works in a separate workspace

    Claude Code makes the change on a copy of your project, inside an isolated container with limited network access. Your own files stay as they are.

  3. 03

    Quarterback checks the result

    It runs your project’s tests and the agreed checks on exactly what changed. A pass means those checks passed. It doesn’t rule out every possible bug.

  4. 04

    You review and decide

    You get the outcome, the evidence behind it and the change itself. Nothing is applied to your project unless you choose to apply it.

One real example

A small change, start to finish.

1 The request

“Show durations under one minute as seconds only: 30 seconds should read 30s, not 0m 30s. Longer durations keep their current format.”

2 The agreed checklist
  • 30,000 milliseconds is shown as 30s
  • 90,000 milliseconds is still shown as 1m 30s
  • Only the file src/duration.js may change
3 The result
  • Both checks passed
  • The project’s own tests passed
  • One attempt, 111 seconds in total
4 The change, for you to review
+  if (minutes === 0) return `${seconds}s`;

One added line (and an updated comment). It was proposed, not applied.

The limits of this example. A person reviewed and edited the checklist before the run, because Quarterback’s automatic drafting didn’t produce a usable one for this request. What a check result can be

Pass
Every agreed check and the project’s tests passed.
Fail
A check or test failed, or a file that was off-limits was changed.
Partial
Some checks couldn’t be decided.
Unresolved
The evidence couldn’t settle it, for example a requirement with no runnable check.

How a run can end

Verified
The change was checked and passed.
Failed / Unresolved
The change was checked, and the result was a fail or couldn’t be settled.
Blocked
The run stopped before checking anything, for example because the requirements weren’t approved or a project dependency was refused. It says nothing about whether a change would have passed.
Error / Cancelled
The run itself broke (such as a timeout or running out of memory) or was stopped.
Supported setup

What you need today.

Quarterback is deliberately narrow while it’s being tested. Anything not listed here isn’t supported yet.

AI assistant
Claude Code only, used with your own Claude subscription or Anthropic API key.
Projects
JavaScript or Node.js projects whose tests use Node’s built-in test runner (node:test).
Computer
Ubuntu 24.04 on a standard 64-bit (x86_64) machine with Docker and 16 GB of memory is the validated setup. macOS: limited successful runs; not a validated supported environment. Windows: not supported.
Also installed
Node.js 20 or newer, git, and Ollama with a small local model that Quarterback uses for its own steps.
Your code
During a run, the task and the code Claude Code reads are sent to Anthropic under your account. Quarterback’s own model calls stay on your machine by default. Data and privacy
Supervised evaluation

Request a supervised evaluation.

We are looking for developers who use Claude Code on JavaScript or Node.js projects and regularly need to check whether a generated change does what was asked. We send you the exact version to install and stay available while you set it up and try it. Then follow the setup guide.

If you opt in, we measure how much correction and review your own tasks need with and without Quarterback, and share the results with you. Metrics are opt-in, tied to your account (not anonymous), deletable by you, and we publish nothing without your say-so.

Progress update · November 7, 2026

What’s done, what isn’t, what we’re testing.

Shipped

In Quarterback’s main code, November 4–5

  • When an automatically written requirements list doesn’t pass Quarterback’s own validation, it makes one correction attempt and then stops with a clear message.
  • It rejects a requirements list that would only allow changes to files marked off-limits.
  • A repeatable way to measure how often local AI models write a usable requirements list.

There’s no packaged release yet; testers install a specific version we give them.

Still unreliable

  • Writing the requirements list automatically. Most automatic drafts are rejected, so evaluations start from a list a person writes or reviews.
  • Setup on the current version hasn’t yet been confirmed end to end on the validated setup.

Being evaluated

  • Does it save review time compared with using Claude Code alone? Not established. Two early, small comparisons showed no measured advantage.
  • Next: confirm one installation path on the current version, then compare against Claude Code alone on tasks whose results are checked independently.
