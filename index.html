Check AI-written code against requirements you approve.

Quarterback runs Claude Code in an isolated workspace, checks the change against a contract you approved, and hands back a patch with the evidence. You decide whether to apply it.

For developers who use Claude Code on JavaScript and Node.js projects and want to know whether a generated change does what was asked.

Where it stands, November 5, 2026. Quarterback is in supervised evaluation and is not yet ready for self-service installation. Automatic contract drafting is not yet reliable, so evaluations start from a contract a person has written or reviewed. We have not yet shown that Quarterback saves review time compared with Claude Code alone.

How it works

Three steps, and you decide at both ends.

  1. 01

    Approve the requirements

    The task is written down as a contract: what must be true, which files may and may not change, and the executable checks that decide the result. The coding agent does not run until you approve it, and changing it later voids the approval.

  2. 02

    Run and check

    Claude Code works in an isolated sandbox. Quarterback then runs your project’s tests and the contract’s checks on the exact change. A separate model reviews only what can’t be executed, such as naming. A failed check can be sent back for another attempt.

  3. 03

    Review the patch

    You get a verdict, the evidence behind it, and a patch labelled with its verification status. Your checkout is unchanged until you apply the patch yourself. Every run is recorded and its verdict can be replayed.

Supported today

A narrow, stated boundary.

Anything not listed here is unsupported. qb doctor checks a machine against this list.

Coding agentClaude Code only, run in Quarterback’s Docker sandbox, with your Claude subscription or Anthropic API key. Cursor, Codex and Gemini are not supported.
ProjectsJavaScript and Node.js, tested with node:test, with an npm lockfile. Projects using another test runner (Jest, Mocha, Vitest and others) are refused before any model call.
What it checksYour project’s node:test suite, and executable checks in the contract: that a module exports something, that a call returns or throws a value, or a sequence of calls. Changes to protected files fail the task. Type checking, linting, browser tests and security scanning are not part of verification.
PlatformUbuntu 24.04 on x86_64, with Docker Engine and 16 GB of RAM, is the validated profile. macOS with Docker Desktop works for development but is not validated. Windows is not supported.
Also neededNode.js 20 or newer, git, and Ollama with deepseek-r1:7b for Quarterback’s local model calls.
Your codeQuarterback’s own model calls stay on your machine by default. During a Claude Code run, the task and the code the agent reads are sent to Anthropic under your account. Telemetry is off unless you opt in, and it is not anonymous. Data flows

Progress update · November 5, 2026

What changed, what remains, what’s next.

“Merged” means merged into Quarterback’s main branch. There is no published release, so nothing here has shipped as a release yet.

Changed

Merged into main

  • Bounded draft recovery. When a drafted contract fails validation, or the model’s reply isn’t valid JSON, Quarterback makes one correction attempt and then stops with a clear message instead of retrying. #19, #20, #21, November 4.
  • Impossible-scope guard. A draft whose only allowed change is a protected file is rejected before any agent runs. #23, November 5.
  • Reproducible drafting evaluation. A harness that measures how often each local model produces a valid contract, with recorded model digests and settings. #22, November 5.

In review, not merged

  • Clearer installation documentation: a shorter README and one linear setup guide. It has been run end to end on macOS, which is not the validated profile.

Remains

  • Automatic drafting is unreliable. Most local drafts still fail validation (see evidence).
  • Contradictions can get through. A draft can pass validation while contradicting the request, and validation doesn’t reliably catch that yet.
  • The current version isn’t qualified for onboarding. The only passing fresh-machine walkthrough is from October 12, at an older commit.
  • Customer benefit is unproven. We have not shown that Quarterback reduces review time or raises accepted task completion.

Next

Planned

  • Qualify one supported installation path at a current commit, on the validated profile, with the evidence recorded.
  • Measure Quarterback against Claude Code alone on tasks whose results are checked independently, not by Quarterback itself.

Supervised evaluation

Request a supervised evaluation.

We are looking for developers who use Claude Code on JavaScript or Node.js projects and regularly need to check whether a generated change does what was asked. We send you the exact commit to install and stay available while you set it up and try it.

If you opt in, we measure how much correction and review your own tasks need with and without Quarterback, and share the results with you. Metrics are opt-in, tied to your account (not anonymous), deletable by you, and we publish nothing without your say-so.
